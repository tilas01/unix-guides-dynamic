# Arch Linux — your manual install guide

Generated by the [*nix Install Guides manual walkthrough](https://tilas01.github.io/Unix-SIT/manual.html).
Cross-check anything you are unsure about against the
[Arch Wiki installation guide](https://wiki.archlinux.org/title/Installation_guide) —
it is the authority, and where it and this disagree it is right.

> **Read this before running any of it.** The partitioning commands are
> aimed at `/dev/nvme0n1` and will destroy everything on it. They do not
> ask twice.

## 0. Before you boot the installer

1. **Verify the image.** Hash it, and get the checksum from a host other
   than the one that served the image — a server that lies about the
   image can hand you a checksum that matches the lie.
   [Verifier](https://tilas01.github.io/Unix-SIT/iso-verify.html).
2. **Lock the firmware down.** Update it, set a supervisor password,
   disable USB and network boot. Without a supervisor password every
   other setting is one unlocked menu away from being undone.
3. **Back up anything you cannot lose** — not to the disk below.
4. **Dual boot preparation**, because the other system is staying:
   - In Windows, as administrator: `powercfg /h off`. Fast Startup
     leaves NTFS hibernated, and resizing it in that state corrupts it.
   - Suspend BitLocker: `manage-bde -protectors -disable C: -RebootCount 2`.
     **Write the recovery key down first, somewhere that is not this
     machine.** Changing the boot configuration changes the TPM
     measurements, and Windows will ask for it.
   - Full **Restart**, not Shut down, before booting the installer.

## 1. Boot the installer and get a network

```bash
ls /sys/firmware/efi && echo UEFI   # confirms firmware mode

# Wireless, if you need it:
iwctl station wlan0 connect YOUR_SSID

ping -c3 archlinux.org
timedatectl set-ntp true
```

## 2. Partition `/dev/nvme0n1`

```bash
lsblk                       # identify the disk by size and model. Twice.
```

You are keeping another operating system, so you are **adding** a
partition rather than repartitioning. Shrink the existing one from
that system's own tools first — Windows Disk Management, or GParted
for Linux — then create one Linux partition in the free space.

```bash
gdisk /dev/nvme0n1
#   n → next free number → rest of free space → type 8300
#   w → write
#
# Do NOT touch /dev/nvme0n1p1. That is the existing ESP and it is shared.
```

### Encrypt

```bash
cryptsetup luksFormat --type luks2 --pbkdf argon2id /dev/nvme0n1p2
cryptsetup open /dev/nvme0n1p2 cryptroot
```

> The passphrase you set here is the one standing between a stolen
> machine and every file on it. There is no recovery if you forget it.

### Format and mount

```bash
# /dev/nvme0n1p1 is the existing ESP. It is NOT formatted.
mkfs.btrfs -f /dev/mapper/cryptroot

mount /dev/mapper/cryptroot /mnt
btrfs subvolume create /mnt/@
btrfs subvolume create /mnt/@home
btrfs subvolume create /mnt/@log
btrfs subvolume create /mnt/@pkg
btrfs subvolume create /mnt/@snapshots
umount /mnt

O="noatime,compress=zstd:3,space_cache=v2"
mount -o $O,subvol=@          /dev/mapper/cryptroot /mnt
mkdir -p /mnt/{home,var/log,var/cache/pacman/pkg,.snapshots,boot}
mount -o $O,subvol=@home      /dev/mapper/cryptroot /mnt/home
mount -o $O,subvol=@log       /dev/mapper/cryptroot /mnt/var/log
mount -o $O,subvol=@pkg       /dev/mapper/cryptroot /mnt/var/cache/pacman/pkg
mount -o $O,subvol=@snapshots /dev/mapper/cryptroot /mnt/.snapshots
mount /dev/nvme0n1p1 /mnt/boot
```

> `@log` and `@pkg` are separate subvolumes so that rolling back to a
> snapshot does not also roll back your logs — you want those to
> explain what went wrong — or throw away the package cache you are
> about to need.

## 3. Install the base system

```bash
pacstrap -K /mnt \
    base linux-firmware sudo vim man-db man-pages texinfo linux linux-headers linux-lts linux-lts-headers btrfs-progs cryptsetup intel-ucode networkmanager sbctl efibootmgr zram-generator

genfstab -U /mnt >> /mnt/etc/fstab
cat /mnt/etc/fstab          # read it before you trust it
arch-chroot /mnt
```

## 4. Configure, inside the chroot

```bash
ln -sf /usr/share/zoneinfo/Europe/London /etc/localtime
hwclock --systohc

sed -i 's/^#en_US.UTF-8/en_US.UTF-8/' /etc/locale.gen
locale-gen
echo "LANG=en_US.UTF-8" > /etc/locale.conf
echo "KEYMAP=us" > /etc/vconsole.conf

echo "archbox" > /etc/hostname
cat >> /etc/hosts <<'EOF'
127.0.0.1   localhost
::1         localhost
127.0.1.1   archbox.localdomain archbox
EOF

passwd                                     # root password
useradd -m -G wheel -s /bin/bash you
passwd you
EDITOR=vim visudo                          # uncomment %wheel ALL=(ALL:ALL) ALL
```

> Windows expects the hardware clock in local time and Linux keeps it
> in UTC, so the two will disagree by your offset. `hwclock --systohc`
> above writes UTC, which is the standards-compliant side; set
> `RealTimeIsUniversal` to `DWORD 1` in Windows to match.

### Tell the initramfs about the encryption

```bash
vim /etc/mkinitcpio.conf
# HOOKS=(base systemd autodetect microcode modconf kms keyboard \
#        sd-vconsole block sd-encrypt filesystems fsck)
#
# sd-encrypt must come BEFORE filesystems, and keyboard before
# sd-encrypt — otherwise you get a passphrase prompt you cannot type
# into, which looks exactly like a broken install.

mkinitcpio -P
```

## 5. Bootloader

```bash
UUID=$(blkid -s UUID -o value /dev/nvme0n1p2)
echo "rd.luks.name=$UUID=cryptroot root=/dev/mapper/cryptroot rootflags=subvol=@ rw" > /etc/kernel/cmdline

# Turn on the unified image preset
sed -i "s|^#\?ALL_config|ALL_config|" /etc/mkinitcpio.d/linux.preset
mkinitcpio -P
```

### Your own Secure Boot keys

```bash
sbctl status                 # firmware must be in Setup Mode
sbctl create-keys
sbctl enroll-keys -m         # -m keeps the Microsoft OEM certificates
sbctl sign -s /boot/EFI/Linux/arch-linux.efi
sbctl verify
```

> `-m` keeps Microsoft's certificates enrolled. On many machines
> the firmware itself is signed by them, and removing them can leave
> you with hardware that will not initialise. Back up the existing
> keys first, and know where "restore factory keys" is in your
> firmware setup before you start.

## 6. Services

```bash
systemctl enable NetworkManager

cat > /etc/systemd/zram-generator.conf <<'EOF'
[zram0]
zram-size = min(ram / 2, 8192)
compression-algorithm = zstd
EOF
```

> zram compresses swap in RAM. Nothing from your memory is written to
> disk, which is one fewer place for a key to end up. It cannot
> hibernate — that needs real disk swap at least the size of RAM.

## 7. Reboot

```bash
exit
umount -R /mnt
cryptsetup close cryptroot
reboot
```

> If it does not come up, boot the installer again, `cryptsetup open`,
> remount, `arch-chroot`, and you are exactly where you were. Almost
> nothing at this stage is unrecoverable.

## 8. After the first boot

Do this from the installed system, logged in as `you`.

```bash
sudo pacman -S --needed \
    hyprland waybar wofi xdg-desktop-portal-hyprland qt5-wayland qt6-wayland polkit-kde-agent pipewire pipewire-pulse pipewire-alsa wireplumber ttf-jetbrains-mono-nerd ufw snapper snap-pac git
```

### Firewall

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw enable
sudo systemctl enable ufw
```

> Default-deny inbound is the highest security-per-keystroke item in
> this whole guide. Everything you did not open is closed.

### Snapshots

```bash
sudo umount /.snapshots && sudo rm -rf /.snapshots
sudo snapper -c root create-config /
sudo btrfs subvolume delete /.snapshots
sudo mkdir /.snapshots && sudo mount -a
sudo systemctl enable --now snapper-timeline.timer snapper-cleanup.timer
```

> With `snap-pac` installed, a snapshot is taken before and after every
> pacman transaction. A broken update becomes a reboot rather than a
> rescue USB.

### Configure what you installed

These need a decision from you, so they are asked rather than guessed.

#### git

git refuses to commit without an identity, and it goes into every commit you ever make — including public ones.

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
```
